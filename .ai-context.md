# Tezos Staking App - AI Context

## Project Overview

This is a Next.js web application that enables users to perform staking operations on the Tezos blockchain, including stake, unstake, and finalize operations introduced in the Paris protocol. The app is deployed at:
- **Mainnet**: [stake.tezos.com](https://stake.tezos.com)
- **Shadownet (testnet)**: [stake-shadownet.tezos.com](https://stake-shadownet.tezos.com)

## Key Features

### Implemented
- ✅ Beacon wallet connection (supports Kukai, Umami, Temple, and other Beacon wallets)
- ✅ All Tezos Paris protocol operations:
  - **Stake**: Lock tez tokens with a baker
  - **Unstake**: Begin the unstaking process
  - **Finalize**: Complete unstaking after the protocol's consensus rights delay (4 cycles on mainnet)
- ✅ Baker selection and delegation
- ✅ Account dashboard with balance information
- ✅ Cookie consent banner
- ✅ FAQ section

### Planned
- ⏳ Detailed baker information (staking fees, rewards history, etc.)
- ⏳ Baker slashing history
- ⏳ Staking rewards display
- ⏳ Delegation rewards display
- ⏳ Slashed rewards tracking

## Architecture Patterns

### State Management
- **ConnectionProvider**: Manages wallet connection state, user address, and Taquito instances
- **OperationResponseProvider**: Handles operation responses and error states
- **React Query**: Used for server-side data fetching and caching

### Wallet Integration
- Uses Beacon protocol for wallet connection
- Supports multiple Tezos wallets (tested with Umami v2.3.0 and Kukai)
- Wallet state persisted across sessions

### Styling Approach
- Chakra UI v3 with custom theme
- Component variants defined in theme/recipes
- Dark mode support via next-themes
- After theme changes, run: `npx @chakra-ui/cli typegen ./theme/theme.ts`

## Important Notes

### Wallet Compatibility
- Fully tested with Umami v2.3.0 and Kukai (as of June 18, 2024)
- Other wallets may gradually add support for stake/unstake/finalize operations

### Tezos Protocol
- Uses Tezos Paris protocol staking features
- Unstaking requires waiting the protocol's consensus rights delay (4 cycles on mainnet) before finalization
- Users can change bakers or end delegation at any time
